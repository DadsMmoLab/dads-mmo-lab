   NOTHING WAS COMMITTED, in this repo or any other.

   **One trap worth the entry.** The first attempt edited the JSON with PowerShell's
   `Set-Content -Encoding utf8`, which on Windows PowerShell 5.1 writes a **UTF-8 BOM** and CRLF.
   The file still looked right in every line-based check; `json.load()` on it died at the first
   byte. Caught by reading the first four bytes of both files
   (`239,187,191,123` against `123,10,32,32`) and redone in Python, writing bytes: the file is now
   BOM-free, LF-only, and `json.loads()` parses it. Do not edit a JSON the engine reads with
   `Set-Content -Encoding utf8`.
