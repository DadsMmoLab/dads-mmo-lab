`--mount-proc` is the whole difference. Without it, `unshare` leaves the caller's `/proc`
mounted, `/proc/1` is this machine's `systemd`, and pid 1's three namespaces read exactly what
the host reads. With it, `/proc/1` is the command `unshare` started. `docker run` behaves like
the `--mount-proc` rows.

Round 8's `_INITIAL_PID_NAMESPACE_INO` table labelled the `--mount-proc` shape
`unshare --net --pid --fork`, and round 8's own new sentence then leaned on that row by number.
The table is now nine rows, each labelled by the exact command, with a `/proc/1` column.

### What the lane's module answers in each shape

`~/yulon-runs/fix9-bug39/pylauncher` on `sys.path`, module at `cd827c0f`:

```
== host uid1000 ==            in_initial_pid_namespace True   where(ufw) unknown
== unshare --pid --fork ==    in_initial_pid_namespace False  where(ufw) other-pid-namespace
== unshare --pid --fork --mount-proc ==
                              in_initial_pid_namespace False  where(ufw) other-pid-namespace
```

In the middle row `/proc/1` is this machine's `systemd` and both comparisons would have answered
correctly — the refusal is a false one, and round 8's sentence for it ("`/proc/1` here is not
this machine's init but the init of a pid namespace of its own … neither namespace question could
be answered") is false there in all three of its clauses. It is true of the bottom row and of
`docker run`.

### The read that would separate them, and why it was declined

```
$ stat -L -c %i /proc/1/ns/pid ; stat -L -c %i /proc/1/ns/net ; stat -L -c %i /proc/1/ns/mnt
stat: cannot statx '/proc/1/ns/pid': Permission denied
stat: cannot statx '/proc/1/ns/net': Permission denied
stat: cannot statx '/proc/1/ns/mnt': Permission denied
$ sudo -n stat -L -c %i /proc/1/ns/pid ; sudo -n stat -L -c %i /proc/1/ns/net
4026531836
4026531840
```

So `/proc/1/ns/pid` costs the same `sudo -n stat` fallback `/proc/1/ns/net` and `/proc/1/ns/mnt`
already pay, and answers `None` -> `"unknown"` where there is no prefix. It buys one shape
(`unshare --pid --fork` from a shell); every container runtime measured here remounts `/proc` and
is not that shape. Declining it keeps a refusal that carries an actionable remedy — leave the pid
namespace, or add `--pid=host` — instead of `"unknown"`, whose remedy is "give the launcher
sudo". The remedy is correct in both shapes either way.

`test_the_pid_question_refuses_both_shapes_without_reading_pid_1` holds that decision: it drives
both signatures, and `_namespaced()` now hands out a truthful `/proc/1/ns/pid` so that spending
the read fails on the answer rather than on a missing key.
