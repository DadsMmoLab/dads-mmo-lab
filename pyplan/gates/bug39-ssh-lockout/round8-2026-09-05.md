### The cause, in one line

`machine_made_zones(*listings)` required a zone to look machine-made in EVERY listing that NAMED
it, and `--permanent --list-all-zones` names every zone that exists. So the permanent listing's
empty reading of `docker` voted against the runtime listing's five bridges, and the docstring's own
escape hatch — *"a zone named in one listing and absent from the other is judged on the listing
that has it"* — could never be reached, because no zone is ever absent from that listing.

### AFTER — same box, same commands, the fixed module

```
daemon      : running
write       : ('FedoraWorkstation', 'docker')
permanent   : ('FedoraWorkstation',)
runtime     : ('FedoraWorkstation', 'docker')
machine_made: ('docker',)
reason      : ssh-preserved allowed: True notes: 0
```

The rule: a reading that binds neither an interface nor a source is **no information** and is
dropped before the vote. A reading that binds a real NIC still disqualifies, in any listing. A
reading that binds a source still disqualifies, in any listing.

## Real — the refusal named the network namespace for a process in pid 1's own

Namespace inodes, read on m910q that day.

```
host                                  pid 4026531836  net 4026531840  mnt 4026531841
host, /proc/1                                         net 4026531840  mnt 4026531841
sudo unshare --net                    pid 4026531836  net 4026533509  mnt 4026531841
sudo unshare --pid --fork             pid 4026533509  net 4026531840  mnt 4026531841
docker run --network=host             pid 4026533512  net 4026531840  mnt 4026533509
  …and /proc/1 as seen from inside it:               net 4026531840  mnt 4026533509
docker run --privileged --pid=host --network=host
                                      pid 4026531836  net 4026531840  mnt 4026533509
```

The fourth and fifth rows are the finding. `_same_namespace_as_pid1()` short-circuits to False
whenever `/proc/self/ns/pid` is not the initial namespace, and round 7 read that False as the CAUSE
"other-network-namespace". BEFORE, round 7's module run inside `docker run --rm --network=host` of
a fedora:41 image carrying `/etc/firewalld`:

```
self pid/net/mnt: 4026533512 4026531840 4026533509
isdir /etc/firewalld: True
where_the_reading_came_from('firewalld') -> other-network-namespace
reads_this_machine('firewalld')          -> False
```

The network namespace is 4026531840 — the host's. And the remedy that sentence carries ends *"if
the rules are meant for that namespace, apply them with the firewall tool inside it"*, which writes
the container's own `/etc/firewalld`: the exact outcome `other-mount-namespace` exists to prevent,
recommended by name.

What IS true in there is that `/proc/1` is the container's init, so both comparisons compare a
namespace with itself — self mnt 4026533509 equals `/proc/1/ns/mnt` 4026533509, while the host's is
4026531841. So the cause is the pid namespace. AFTER, with the fixed module, all five shapes:

```
host                                                -> this-machine
sudo unshare --net                                  -> other-network-namespace
sudo unshare --pid --fork                           -> other-pid-namespace
docker run --network=host                           -> other-pid-namespace
docker run --privileged --pid=host --network=host   -> other-mount-namespace
```

The last row is the new remedy's own promise, checked: *"add `--pid=host` so `/proc/1` is this
machine's — the probe can answer then, and will still refuse a container that writes its own
`/etc`"*.

## Nit — the fixture

`_YULON_FEDORA_LISTING` was one hand-written string documented as "`firewall-cmd --list-all-zones`
form", binding `docker0` to `docker` and `enp0s31f6` to `FedoraWorkstation` permanently — the one
shape real Docker does not produce — and the test that used it hand-fed `machine_made=('docker',)`
into `_firewalld_plan` past the derivation it was checking. It is now `_YULON_FEDORA_PERMANENT`
(three of the fifteen blocks, copied out of that box's own `--permanent --list-all-zones`; the
trailing space after an empty field is not reproduced and the departure is recorded in the
docstring) and `_YULON_FEDORA_ACTIVE` (all four lines of its `--get-active-zones`), and the test
drives `detect_firewalld_zones()` and asserts the two argvs it asks first.

## The stopped-daemon branch

Asked read-only on yulon-fedora with the daemon running: `firewall-offline-cmd --list-all-zones`
returned all fifteen zones with `interfaces:` and `sources:` empty — it is the permanent config,
where Docker's bridges are never bound. `zones_from_listing(..., bound_only=True)` therefore keeps
only `('FedoraWorkstation',)`, the `(default)` tag alone, and an unbound `docker` zone cannot reach
`permanent` or `write` for a breadth note to name. The gate is inert there and harmlessly so; one
sentence in the code says it, and the path is unchanged.
