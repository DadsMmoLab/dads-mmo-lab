=== ADDENDUM: what actually differs between the two installs, and what does not
========================================================================
The first diff above used the 'docker compose config --format json' route and
reported 26 differing lines. NONE of them is a difference between the two
INSTALLS. Two separate causes, both measured rather than assumed.

(a) CAPTURE ROUTE. The 08-31 capture beside the fixture is plain
    'docker compose config' (YAML): gate-compose-config.yml, 219 lines, first
    line 'name: yulon-wow-wotlk-243c46e3'. The --format json route additionally
    emits 'command: null' and 'entrypoint: null' on every service and
    'ipam: {}' on every network. Taking the SAME route 08-31 took removes all
    ten of those lines. Measured, both files, below: 219 lines each, and
    grep -c 'command: null|entrypoint: null' is 0 in each.

(b) AN UNDOCUMENTED STRIP IN THE COMMITTED FIXTURE. Four nested name keys --
    networks.ac-network.name, networks.default.name, volumes.client-data.name,
    volumes.db-data.name -- are PRESENT in the 08-31 raw capture
    (~/gate-compose-config.yml lines 212, 214, 217, 219), PRESENT in mine (the
    same four line numbers), and ABSENT from tests/data/wotlk-compose-config.json
    (0 occurrences of the string yulon-wow-wotlk in it at all). The E.2 brief
    documents only raw.pop('name', None) at the TOP level, which cannot reach
    them. So the fixture carries a strip its own brief does not describe.

    That strip is the ONLY residue. Taking the 08-31 route, my capture differs
    from the fixture in 16 lines and all 16 are those four keys.

WHAT THAT LEAVES. The services block -- all five services, every image, port,
volume, environment key and depends_on -- is IDENTICAL between the 2026-08-31
install and this independent 2026-09-04 one. support_compose.compare() agrees
from the other direction: 0 service differences.

THE ONE STACK DIFFERENCE IS NOT A RUN DIFFERENCE EITHER, and this was checked
rather than argued. compare_stack() reports 'project: the native stack has no
name:' because the documented transform strips the top-level name from whatever
is placed on the native side. Asked three ways it answers the same:
    compare_stack(fixture, fixture) -> [that one line]
    compare_stack(mine,    mine)    -> [that one line]
    compare_stack(fixture, mine)    -> [that one line]
Same answer with both sides identical, so it is a property of the transform,
not of either run.

INSTALL ID IS NOT A DIFFERENTIATOR HERE, contrary to what the task brief
assumed. Both runs installed into /home/pk/wowserver and the id is derived from
that path, so BOTH are 243c46e3 and nothing in either capture distinguishes the
runs by id. What makes this capture independent is the RUN: a fresh clone of
mod-playerbots/azerothcore-wotlk taken 2026-09-04 (core rev 47960183bb03+, see
gate-auth.log line 5), compiled from an emptied BuildKit cache (ccache-stats.txt
T0), on a box whose previous install had been removed (box-preparation.txt).
