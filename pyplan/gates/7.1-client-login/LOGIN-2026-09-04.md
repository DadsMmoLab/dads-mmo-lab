## Which file actually decides the realm — the question the state note left open

`Data/enUS/realmlist.wtf` decides. It was left at `100.99.161.102` on purpose to find out.

Measured, in this order:
1. `WTF/Config.wtf` set to `100.71.125.58`, client restarted → login screen still read
   `AzerothCore / 100.99.161.102`.
2. `Data/enUS/realmlist.wtf` then set to `100.71.125.58`, client restarted → login screen
   read `AzerothCore / 100.71.125.58`.

So `realmlist.wtf` overrides `Config.wtf`'s `SET realmList`, and the `vx` server list in
`interface/loginui.lua` is a *convenience picker*, not the thing the client obeys on
startup. Correcting `wow-client-realmlist-lives-in-loginui.md`: loginui.lua is where a
server is CHOSEN in the UI; realmlist.wtf is where the client READS one at launch.
Backups: `Config.wtf.bak-before-yulon-20260904-2027`,
`realmlist.wtf.bak-before-yulon-20260904-2029`.

```

    "SELECT id, username, last_login, last_ip, online, failed_logins
       FROM acore_auth.account WHERE username='YULON';"
101   YULON   2026-09-04 18:30:22   172.19.0.1   1   0
```

`18:30:22` UTC is the client's `20:30:22` CEST — the same event. `online=1` while the
client sat at character select. `failed_logins=0`: it worked first try.
`last_ip` is `172.19.0.1` because the connection arrives through docker's bridge; that
is the gateway, not the client.
