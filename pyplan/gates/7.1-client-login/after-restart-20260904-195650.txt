4. ONE CAVEAT ABOUT gx.log AS A SIGNAL -- it flushes at EXIT, not live.
--------------------------------------------------------------------------------
At 19:56:27, 46 s after launch and with the login screen plainly on screen, gx.log was
STILL 0 bytes / LastWriteTime 19:55:41. The renderer is up regardless -- the window
class, the rendered login screen and GlueXML.log prove it.
The 18:47 run shows why: its gx.log CONTENT is timestamped 18:47:42 - 18:47:52, but the
FILE's LastWriteTime is 18:48:36 -- about 44 s later, when that process exited. The
client buffers gx.log and flushes it on shutdown.
Consequence for future runs: "gx.log is 0 bytes" is only meaningful AFTER the process
has exited. While the client is alive, use the window class (GxWindowClassD3d vs
#32770) and GlueXML.log instead. Before the restart the 0-byte reading was decisive
only because the process had already exited, with the #32770 dialog to go with it.
