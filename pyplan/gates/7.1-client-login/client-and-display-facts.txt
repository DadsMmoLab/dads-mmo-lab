4. WHAT WAS STAGED, AND HOW TO FINISH IN FIVE MINUTES ONCE A SCREEN EXISTS
--------------------------------------------------------------------------------
    Credentials. The brief said the password is in account-lan.log; it is not --
    that log records only "keeping its password". It is in the driver that made
    the account, on the box: /home/pk/gate0904/gate-account-lan.py
        USERNAME = "gate0904"      -> the row is GATE0904, account_id 101
        PASSWORD = "gate0904pw"
        GM_LEVEL = 3
    Transport. The laptop cannot route 172.30.55.119 (Test-NetConnection -Port 3724
    -> False); that address is the Hyper-V internal network. An ssh tunnel closes
    that, and it was built and PROVEN before the client was launched:
        ssh -N -L 3724:127.0.0.1:3724 -L 8085:127.0.0.1:8085 yulon-ubuntu
        Test-NetConnection 127.0.0.1 -Port 3724 -> True
        Test-NetConnection 127.0.0.1 -Port 8085 -> True
    Realm hand-off. A tunnelled client arrives at the authserver as 127.0.0.1, and
    src/server/shared/Realms/Realm.cpp:28-41 on this very box says:
        if (clientAddr.is_loopback())
            if (LocalAddress->is_loopback() || ExternalAddress->is_loopback())
                realmIp = clientAddr;            // <- what we want
            else realmIp = *LocalAddress;        // 172.30.55.119, unroutable here
    so the realm must advertise a loopback LOCAL address for the duration:
        UPDATE acore_auth.realmlist SET localAddress='127.0.0.1' WHERE id=1;
    This was applied and then PUT BACK; the row is 172.30.55.119 / 172.30.55.119
    again (see server-side-after-attempt.txt, last line). `address` was never
    touched, so clause 15's "advertises 172.30.55.119" still reads as the 7.1 lane
    left it.
    Client config. WTF\Config.wtf `SET realmList` overrides data\enus\realmlist.wtf
    on this client -- both were pointed at 127.0.0.1 and both have been RESTORED
    (100.99.204.5 and 100.99.161.102 respectively). Backups kept as *.lanec-bak.
    DXVK's d3d9.dll was renamed aside for attempt (2) and is back in place.
    NOTE: data\enus\realmlist.wtf.bak-127 already existed before this lane -- an
    earlier run did the same 127.0.0.1 substitution here.

    To finish: open the lid (or plug a monitor in), then
      1. ssh yulon-ubuntu "docker exec ac-database mysql -uroot -ppassword -e \
           \"update acore_auth.realmlist set localAddress='127.0.0.1' where id=1;\""
      2. ssh -N -L 3724:127.0.0.1:3724 -L 8085:127.0.0.1:8085 yulon-ubuntu
      3. set WTF\Config.wtf  SET realmList "127.0.0.1"
      4. run C:\wow335ahd\wow.exe, log in GATE0904 / gate0904pw, create a character
      5. read the three witnesses below, then put localAddress back to 172.30.55.119
