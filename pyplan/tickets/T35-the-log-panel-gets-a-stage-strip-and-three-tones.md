## What is true today

- `LogPanel` (`pylauncher/yulon/ui/widgets/log_panel.py`) is one `QPlainTextEdit` fed plain strings (`LineSource = Callable[[], Iterator[str]]`), each stamped `[h:mm:ss]` in `append()`; a header row holds the status label, the elapsed clock and Stop. No colour, no progress widget. The same panel serves the install output and the Console tab.
- The engine's spine `_staged()` (`native.py`) yields `Step N of M (P%): <name>` and `--- <name>` for every stage; gate scripts, log captures and the interrupted-import watchers grep `^--- `, and dozens of tests compare the yielded lines literally. **Those two line shapes do not change.**
- The clone stage yields `Cloning <repo> into <dest>` and then nothing until git returns: `git.py` `NativeGit.clone()`/`_update()` run through `_run_git()` → `runner.run()` (blocking). Git's own progress goes to stderr, `\r`-separated, and is never read. `runner.stream()` yields stdout live but withholds stderr until exit (its docstring says why), so it cannot carry git's progress as it is.
- Subprocess output that IS relayed live — `docker build --progress plain` (`docker.py` ~3324, `run_attached()` ~3238), the extractors and the mmap generator (`families/extract.py`) — arrives in the panel indistinguishable from the app's own sentences. The T30 install on yulon-arch wrote 97 minutes of `[Map 230] Building tile [32,32] (08 / 12)` lines at the same weight as "Cloning …".

## Definition of done

**1. Two prefixes, one control character.** `yulon/ui/lines.py` (new, no Qt): `PROGRESS = "\x1eprogress "` and `TOOL = "\x1etool "`, a `parse(line) -> Parsed` returning `kind` (`stage`, `marker`, `sentence`, `tool`, `warning`, `failure`, `progress`), the display `text` (prefix stripped), and for `progress` the `stage`, `percent: int | None` and `text`. Classification by shape, in this order: `PROGRESS`-prefixed → progress (`<stage> <percent|-> <text>`; a malformed one is a `sentence` with the prefix stripped, never lost); `TOOL`-prefixed → tool, unless the payload matches the warning or failure shapes, which win (a compiler's `warning:` is still amber); `^Step \d+ of \d+` → stage; `^--- ` → marker; `\bFAILED\b|^INSTALL FAILED|^error:|\berror\b.*:|\[fail\]|refused` → failure; `^warning:|\[warn\]|\bWARNING\b` → warning; else sentence. Tests per kind with the named mutation (drop one regex → that case falls to sentence).

**2. The panel draws tones and a strip.** `append()` routes through `lines.parse()`: `stage` bold, `marker` muted, `sentence` normal, `tool` dimmed, `warning` amber on a soft amber band, `failure` red on a soft red band and 500 weight (`QTextCharFormat` per kind, colours from one palette dict at module level so the test can read them; the dark/light question is Qt's palette — pick amber/red/dim relative to `QPalette.Text` so they read on both). `progress` lines are NOT appended: they update the strip. `text()` returns the stamped display text with every prefix stripped, so every existing test that reads `panel.text()` passes unchanged; a test asserts a `TOOL`-prefixed line's `text()` is the payload alone. **The strip** sits in the header between the status label and the elapsed clock: a small label `Step 3 of 9 · clone-core` (from the last `stage` line — parse `N`, `M`, `name` from it; the format is the engine's, unchanged) and a `QProgressBar` (Qt's own; range 0–100 when the last progress line had a percent, `setRange(0, 0)` busy otherwise; hidden while idle; red when the run ends `ok=False` — set through the same palette). The right-hand text of the strip is the progress line's `text`. Elapsed and Stop stay where they are. Tests: a `stage` line sets the strip label (mutation: parse `M` wrongly → the test fails); a progress line with a percent sets a determinate bar at that value and does not append (mutation: append it anyway → `text()` gains a line); a `-` percent sets busy; `run_finished(False, …)` turns the bar red and leaves the label; the panel's `minimumSizeHint().width()` measured before and after (the T32 wrap test's bound) so the strip cannot reopen the width bug.

**3. Git progress streamed.** `runner.stream_progress(command, cwd) -> Iterator[str]` (new; beside `stream()`, not changing it): stdout and stderr read live on two threads, stderr split on `\r` AND `\n`, each fragment yielded as it arrives; non-zero exit raises `CalledProcessError` as `stream()` does; the `\r`-split rule and why git needs it in the docstring (past tense: what git prints). `git.py`: the `Git` Protocol gains `clone_lines(self, spec) -> Iterator[str]` with the module-level default `def clone_lines(git, spec): git.clone(spec); return iter(())`-shaped fallback so every fake in the tests stays valid without edits; `NativeGit.clone_lines()` runs the clone (and `_update()`'s fetch) with `--progress` through `stream_progress()`, yielding each git fragment as `PROGRESS + f"{stage} {percent} {text}"` when it parses `Receiving objects:\s+(\d+)%` / `Resolving deltas:\s+(\d+)%` / `Compressing objects:\s+(\d+)%` / `Updating files:\s+(\d+)%`, and as `TOOL + text` otherwise; the clone stage in `native.py` (`Cloning {repo} into {dest}` at ~4346) relays `clone_lines()` instead of calling `clone()`; the stage name in the progress line is the current stage's. The containerized git path (`git.py` ~937, `alpine/git`) does the same through `docker` streaming if `run_attached()` can carry stderr; if it cannot in one bounded attempt, it keeps `clone()` and says so in the report. Tests: a recorded stderr sample (a real `git clone --progress` capture with `\r`, in `tests/fixtures/`) fed through a fake process yields the expected `PROGRESS` lines with percents 0→100 and the `TOOL` lines between (mutation: split on `\n` only → the percents collapse to the last one); the sparse clone path unchanged.

**4. Relayed output marked as tool output.** Every site that yields a subprocess's lines into the panel prefixes them with `TOOL`: `docker.run_attached()`'s relay (the build, the no-deps compose start), `families/extract.py`'s extractor and mmap relays, `docker.follow_logs()` for the Console tab (the server's own log is tool output), and any other `yield from runner.stream(...)`/`run_attached(...)` site found by grep. The app's own sentences at those sites stay unprefixed. **Percent sources** yielded as `PROGRESS` lines where a number exists: BuildKit `^#\d+ \[[^\]]* (\d+)/(\d+)\]` → `k*100//m`, the compiler's `\[\s*(\d+)%\]` inside a build line → that percent (the later wins), the mmap generator's `Building tile \[\d+,\d+\] \((\d+) / (\d+)\)` → per-map percent with the text `Map 230 · tile 8 of 12`.
